# AI Agent 工具集成可行性分析矩阵 (AI-to-Tool Integration Matrix)

针对 AI 调用外部工具的场景，根据“工具暴露程度”与“重构成本”，整理出以下 6 种典型情况及应对策略：

---

## 1. CLI 命令行工具类

### 情况 1：原生 AI 友好型 CLI
* **特征**：支持 JSON/CSV 格式化输出；有清晰的 `--help` 文档；无交互式确认（或支持 `-y`）；报错信息明确。
* **AI 集成策略**：**直接映射**。编写 JSON Schema 直接定义工具参数，通过 `subprocess` 获取输出并由 Agent 直接解析。

### 情况 2：AI 不友好型 CLI
#### 2.1 有源码（开源）
* **特征**：输出为非结构化文本（杂乱的 stdout）；存在强制交互（如提示输入密码/确认）；参数逻辑复杂。
* **AI 集成策略**：**重构/包装 (Sidecar)**。在原代码基础上封装一层专门给 AI 用的接口，或通过 MCP (Model Context Protocol) 协议标准化。
#### 2.2 无源码（闭源）
* **特征**：典型的黑盒工具，无法修改逻辑。
* **AI 集成策略**：**解析器模式 (Wrapper)**。使用传统的正则表达式或利用 LLM 作为一个“结构化提取层”，将混乱的文本转为 Agent 可读的 JSON。

---

## 2. 非 CLI/接口类

### 情况 3：无 CLI 界面
#### 3.1 有源码（库/函数级别）
* **特征**：没有可执行程序，但有核心逻辑库（Python 包、C++ 源码等）。
* **AI 集成策略**：**原子化暴露**。直接编写适配器（Adapter）将核心函数暴露给 Agent，无需经过命令行层。
#### 3.2 有 API 接口及文档 (REST/gRPC)
* **特征**：典型的 Web 服务或微服务，有标准的调用契约。
* **AI 集成策略**：**协议对接**。这是最理想的模式。通过解析 OpenAPI (Swagger) 文档，让 Agent 像操作函数一样进行远程调用。
#### 3.3 无 CLI 也无 API 文档
* **特征**：最极端的黑盒（如遗留的二进制文件、私有协议、或仅有 GUI）。
* **AI 集成策略**：**黑盒逆向 / UI 自动化**。
    * **方案 A**：对流量进行抓包分析，强行还原接口逻辑。
    * **方案 B (Computer Use)**：通过视觉大模型（Vision Agent）模拟人工操作鼠标键盘。

---

## 3. 集成决策建议

| 优先级    | 情况类型        | 推荐处理方式                       | 成本  |
| :----- | :---------- | :--------------------------- | :-- |
| **P0** | 情况 1, 3.2   | **直接接入**：定义 Schema 即可        | 低   |
| **P1** | 情况 2.1, 3.1 | **封装转换**：编写轻量级适配层            | 中   |
| **P2** | 情况 2.2, 3.3 | **智能代理/RPA**：用 LLM 辅助解析或视觉模拟 | 高   |
